1.1

Why a chat forgets

Everything a chat knows sits in one context window. When the chat ends, the window is thrown away, so only what was written to a file survives.

2.1

One request, end to end

I type one line. Follow it through the machine in six steps, from the rules to a chat a week later.

00

I type one line.

A fresh chat opens with an empty window, like every chat.

01

It reads the rules.

CLAUDE.md comes first. It says what may never happen and the order of everything read next.

02

It reads the kernel.

HOT.md is short and capped by a script. It holds what is live right now, and every chat reads it.

03

It opens its own file.

One chat.md per chat, so two chats never write to the same place. It reads the folder’s own notes and checks the skills list for a written procedure.

04

It writes as it works.

Each decision is saved the moment it is made, so nothing is lost if the chat is cut off.

05

The merge carries it.

Three times a day one locked script copies decisions into shared memory and keeps the kernel current. It only ever adds.

06

Next week, it is found.

A new chat reads the rules and the kernel, which points it to last week’s decision in memory.

3.1

The rules come first

A chat that has read nothing must still be safe, so the rules in CLAUDE.md, the Constitution, load before anything else. When two rules disagree, a fixed order decides, and one rule sits outside the order entirely.

4.1

Memory that cannot collide

On August 16 two chats saved at the same moment and one record vanished. Now each chat writes only its own file, and one locked merge is the only thing that writes to shared memory.

5.1

Work while I sleep

Nine routines run on a clock with nobody at the keyboard. At 6:02 one of them writes and publishes the paper, The Morning Brief. Every run leaves a receipt, and one routine, housekeeping, checks that the receipts exist.

6.1

Nothing ships on its word

Claude can say “done” and be wrong. So anything public passes gates, scripts that stop the job with an error. Every failure is written up, and a fix that keeps mattering becomes code.

7.1

Where it stops

Three things always come back to me: anything that can charge me, anything sent as me, and deleting. A fourth is never obeyed at all: instructions hidden in outside text.

8.1

Break it

Every part exists because something went wrong without it. Switch one off and see what fails.

That is the whole idea. A chat forgets, so everything that matters lives in files it must read, write and check.
