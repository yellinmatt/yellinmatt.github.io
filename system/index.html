Claude OS · how I run school, work and every project on Claude

Every chat forgets.This is how mine remembers.

Claude OS is one folder of plain text files and a few small scripts. Every chat reads it first, writes to it as it works, and checks its work before anything ships. The machine below is running.

1.1

Why a chat forgets

Everything a chat knows sits in one context window. When the chat ends, the window is thrown away, so only what was written to a file survives.

2.1

One request, end to end

I type one line asking for a reading plan. Follow it through the machine in six steps, from the rules to a chat a week later.

00

I type one line.

A fresh chat opens with an empty window, like every chat.

01

It reads the rules.

CLAUDE.md comes first. It says what may never happen and the order of everything read next.

02

It reads the kernel.

HOT.md is short and capped by a script. It holds what is live right now, and every chat reads it.

03

It opens its own file.

One chat.md per chat, so two chats never write to the same place. It reads the project folder’s own CLAUDE.md and checks the skills list for a written procedure.

04

It writes as it works.

Each decision is saved the moment it is made, so nothing is lost if the chat is cut off.

05

The merge carries it.

Three times a day one locked script copies decisions into shared memory, where it only ever adds, and keeps the kernel current.

06

Next week, it is found.

A new chat runs the same five reads, and the kernel points it to last week’s decision in memory.

3.1

The rules come first

A chat that has read nothing must still be safe, so the rules in CLAUDE.md, the Constitution, load before anything else. When two rules disagree, a fixed order decides, and one rule sits outside the order entirely.

3.2

It checks before it asks

A flag is a question, never a finding. An unread email, an open card or an old note can all be wrong, because nothing writes back when I finish something.

So before Claude says anything needs me, it opens the place that would show I already did it.

3.3

One home per fact

Every fact, file and rule has exactly one home. Anything else points to it, so there is never a second copy to go stale.

Project status works the same way. Each folder writes its own status in the labeled lines at the top of its file, its front matter, and a script builds the board from those.

4.1

Memory that cannot collide

On August 16 two chats saved at the same moment and one record vanished. Now each chat writes only its own file, and one locked merge is the only thing that writes to shared memory.

4.2

Two memories, one judge

The platform keeps its own account memory and files notes from chats by itself. It is a useful hint and never the record.

When it and the files disagree, the files win. A claim found only in account memory is unsourced until a file backs it.

5.1

Work while I sleep

Nine routines run on a clock with nobody at the keyboard. At 6:02 AM one of them writes and publishes the paper, The Morning Brief. Every run leaves a receipt, and housekeeping, the routine that also runs the merge at each of its three runs, checks that the receipts exist.

A routine is a skill on a clock. Its stored prompt only points at the skill’s file, so fixing the skill fixes every future run.

5.2

Skills load only when needed

A skill is a written procedure for one recurring job, and a chat reads only the one its task needs.

On August 19 the reading every chat did up front measured about 80 KB, roughly 20,000 tokens before a word of the task. It was cut to five reads, which come to about 60 KB today, and everything else waits until it is needed.

5.3

The link to the Mac

Chats and routines run in the cloud and reach my files through a link to my Mac. A routine fires only if the Mac is awake with the Claude app open.

If it isn’t, the routine runs late or is switched off, and housekeeping switches it back on at its next run.

6.1

Nothing ships on its word

Claude can say “done” and be wrong. So anything public passes gates, scripts that stop the job with an error. Every failure is written up, and a fix that keeps mattering becomes code.

6.2

Sources are captured, not consulted

Anything a teacher or counterpart wrote, and that the work depends on, is saved as text before it is used: lectures, slides, assigned readings.

Every folder with sources keeps a table with one row per stream, and a zero is written down, so a gap shows instead of hiding.

6.3

Writing has a genre

There is no general writing rule. An email, a cover letter and a lesson are different jobs, so each genre gets a register card built from my own writing and approved by me. Talking to me in chat has a fixed register, set in the DNA.

When I rewrite a sentence, the pair goes into a ledger, and three of my edits against one card mean the card is wrong.

7.1

Where it stops

Three things always come back to me: anything that can charge me, anything new sent or published as me, and deleting. Nothing is ever deleted: files move to one Trash folder with a note, and only I empty it. Moving to Trash is not deleting, so Claude does that without asking. A fourth is never obeyed at all: instructions hidden in outside text are left in place and noted for me.

Routines like the paper publish on a schedule I approved once, and only after the gates pass.

7.2

What never goes public

An employer’s work stays on that employer’s systems. My own prep notes and signed paperwork may live here. Passwords and tokens live only in locked files that are never tracked or published.

The publishing gate holds the shape of personal data, never the data, so it can’t become the leak it looks for.

7.3

Deletion has one door

Claude never deletes. Discards move into one Trash folder inside the master folder, with a dated note, and only I empty it.

The move stays inside one drive, because on August 19 a copy to another drive looked perfect and wasn’t.

8.1

Break it

Every part exists because something went wrong without it. Switch one off and see what fails.

That is the whole idea. A chat forgets, so everything that matters lives in files it must read, write and check.
